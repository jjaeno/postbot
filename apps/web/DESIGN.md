# Postbot UI

Postbot is a working content application. Use the visual restraint of Apple interfaces while keeping controls familiar on the web. Keep the existing sidebar, page navigation and business behavior.

## References

- [Apple design analysis](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/apple/DESIGN.md), community analysis of Apple.com.
- [Apple interface playbook](https://github.com/sankalpaacharya/apple-human-interface-skills/blob/main/skills/playbook/apple-look.md), community guidance for app interfaces.
- [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines), official reference.

## Visual rules

- White content area, neutral light gray sidebar. Use blue `#0066cc` for actions and selection. Preserve semantic error and warning colors.
- Main text `#1d1d1f`, secondary text `#626267`, faint separators `#e5e5e7`.
- Use the system font stack. SF fonts appear only on devices where they are available; do not download Apple fonts.
- Page titles 28–34px, section headings 18px, controls and ordinary copy 14–15px. Avoid tiny decorative labels.
- Use 8px spacing increments, 24–32px between sections, and 40–48px desktop content margins.
- Keep panels flat and restrained. No gradients, ornamental badges, generic marketing slogans or numbered onboarding decorations.
- Keep related filters together above their results. Secondary experiment and strategy tools live under a clearly labelled disclosure.
- Empty states describe the missing content and provide one relevant next action. Never invent metrics or example charts.
- Preserve form input while changing pages. Keep keyboard focus visible and mobile controls easy to tap. Respect reduced motion.

## Scope

These rules govern presentation and navigation. Do not change API requests, validation, permissions, publishing, costs, or automation rules as part of a visual pass.
