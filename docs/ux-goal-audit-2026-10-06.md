# 최초 목표 기준 화면 UX 직접 점검

이 문서는 `137d3fa`에서 수행한 수정 전 점검 기록이다. 이후 보완 결과와 현재 지원 한계는 [19.4 UX 보완 결과](ux-remediation-2026-10-06.md)를 따른다.

## 결론

**최초 명세의 모든 기능을 화면만으로 사용할 수 있는 상태는 아니다.** 채널 생성·샘플 제작·검수·최초 다중 플랫폼 예약은 실제 로컬 서비스에서 동작하지만, 예약 변경에는 출시 차단 수준의 재현 가능한 결함이 있다. 화면 누락과 모바일·검수 안내 문제도 남아 있다.

이전 `v1-acceptance-report.md`의 내부 blocker 0 판정과 이번 실제 UX 결과는 충돌한다. 해당 판정을 전체 최초 명세의 화면 사용성 완료로 확대 해석하면 안 된다. 이번 요청은 점검이므로 서비스 코드와 DB schema는 수정하지 않았다. 새 기능 구현·보완 커밋도 하지 않았다.

## 기준과 방법

- 점검 기준일: 2026-10-06, 사용자 시간대 Asia/Seoul.
- 대상 코드: `137d3fa` (`fix: 출시 회귀 결함과 운영 검증 보완`).
- 최초 첨부 요청의 목표: 코드·DB·API 도구·콘텐츠 ID 직접 입력 없이 화면만으로 설정→소재→제작→진행→검수→예약→게시 결과 확인.
- 함께 대조한 문서: `Postbot_기능_UX_명세서_v0.2.docx` 전체, `feature-ux-pre-release-addendum.md`, 현재 19단계 완료 범위.
- 실제 Chromium 브라우저에서 클릭·입력·선택·재생·새로고침·키보드·모바일 크기 변경을 실행했다. 기존 13개 mock Playwright 테스트를 재실행한 결과로 대체하지 않았다.
- 실제 Nest API, 전용 MySQL, Redis/BullMQ, MinIO, worker, Chromium/FFmpeg를 사용했다. LLM·이미지·음성·SNS OAuth/게시/분석 외부 제공자는 Fake다. 실제 SNS나 유료 API를 호출하지 않았다.
- 앱 화면 조작은 사용자 대신 수행하고, 별도 API 읽기는 저장 결과·상태 검증에만 사용했다. 점검 도구에서 내부 ID를 읽는 것은 사용자가 화면에서 ID를 입력하는 기능으로 간주하지 않았다.
- 브라우저: 기본 1440×1000, 모바일 390×844, timezoneId Asia/Seoul.
- 최종 전용 DB: `postbot_ux_20261006_test`. 개발 DB·Redis·MinIO와 별개다. 운영 설정이나 키를 읽어 사용하지 않았다.
- 임시 로컬 포트: web 5173, API 13000, 테스트 MinIO 19000. 미디어의 Docker 전용 `minio:9000` DNS는 테스트 브라우저에서 loopback으로 운반하되 서명 Host를 유지했다. 이는 운영 public storage 접근 검증이 아니다.
- 증거: `.artifacts/ux-audit-20261006/results.json`, 항목별 PNG, 직접 실행용 browser driver와 audit 스크립트. 쿠키·비밀번호·OAuth token·서명 URL은 보고서/결과 JSON에 저장하지 않았다.

## 우선 보완해야 할 재현 결함

### P1 — 예약을 변경하면 다시 저장할 수 없음

1. 샘플 검수·승인을 완료한 공통 콘텐츠를 YOUTUBE, INSTAGRAM, TIKTOK에 순차 예약한다. 첫 예약 세 건은 성공한다.
2. 캘린더에서 YOUTUBE `예약 변경`을 누르고 확인한다. 기존 계획이 CANCELLED가 된다.
3. 검수의 YOUTUBE 탭에서 다른 미래 시각을 입력하고 `게시 계획 만들기`를 누른다.
4. POST `/publishing/plans`가 **500**을 반환한다. 화면 상단은 `요청을 처리하지 못했습니다.`만 표시한다. YOUTUBE는 CANCELLED로 남고 다른 두 플랫폼만 SCHEDULED다.

원인: `PublishingService.schedule` → `createScheduledPlan`은 새 `PublishPlan`을 생성하지만 DB의 `@@unique([contentItemId, platform])`에는 취소된 기존 행도 포함된다. 실제 Prisma 오류는 `publish_plans_contentItemId_platform_key`, P2002였다. 날짜·시간대 오류가 아니다. 취소 후 재예약 경로와 DB 모델을 함께 정합화해야 한다.

### P1 — 선택 플랫폼의 제목 수정이 다른 플랫폼에 전파됨

YOUTUBE 제목만 `UX 검증 게시물 YT`로 바꾸고 저장한 뒤, 손대지 않은 INSTAGRAM/TIKTOK을 예약했다. 두 플랫폼의 예약 title도 같은 값으로 바뀌었다.

`updateMetadata`가 공통 `ContentItem.title`까지 변경하고, 다른 출력은 별도 `reviewTitle`이 없으면 이 공통 제목으로 fallback한다. 플랫폼별 메타데이터 편집의 격리가 깨진다. 별도 출력 제목과 공통 기획 제목의 책임을 분리해야 한다.

### P1 — 채널 생성 후 운영 규칙을 화면에서 수정할 수 없음

설정 수정 패널에는 이름·언어·시청자·말투·훅·CTA·길이·브랜드·음성·AI 비율·일일 게시 한도가 있다. 그러나 주제/설명, 수집 키워드·허용/제외 출처, 최신성/수집 빈도, 요일·시간·시간대, 최소 재고, 승인형↔완전 자동형, 실패 행동은 변경할 입력이 없다. 마법사는 저장된 채널의 일반 수정 화면을 대신하지 않는다.

### P1 — 분석·최적화의 화면 경로가 끊김

채널/플랫폼/7·30·90일 조회 선택은 있지만, 데이터 동기화·재동기화, 개선안 생성, 자동 적용 허용 필드/변화폭/보호 설정을 조작할 UI가 없다. API에는 해당 기능이 존재한다. 자동 제작의 게시 직후 한 번 분석 sync하는 코드 경로는 있으므로 **분석 수집 자체가 전혀 없다고 판정하지 않는다.** 다만 수동 게시·후속 성과 갱신·제안 생성까지 화면만으로 이어갈 수 없다. 제안 빈 상태의 안내는 사용자가 실행할 수 없는 `동기화하고 비교 집단 생성`을 요구한다.

### P2 — 모바일 검수 화면 넘침

390px viewport에서 document scrollWidth가 **458px**이다. 검수 결과 카드·영상·제목/설명 입력·재생성 버튼의 오른쪽이 잘린다. 실제 생성 결과와 긴 권리 purpose가 있는 데이터로 재현했다. mock의 짧은 데이터로 통과한 모바일 테스트와 다르다. 증거: `18-mobile-review.png`.

### P2 — 검수·오류·상태 안내

- 설명을 일반 문구로 바꾸면 `AI_DISCLOSURE_REQUIRED` / `review`가 되어 승인 버튼이 비활성화된다. 표시 누락을 차단하는 것은 정상이나, 화면에는 영어 `AI disclosure requires manual confirmation.`뿐이며 확인/표시 추가 조작이나 한국어 해결 안내가 없다. 코드의 판정 문자열을 확인한 뒤 화면 설명에 `AI generated`를 입력해야 검사를 통과했다. 사실·민감성 등의 `review` 판정에 대한 안전한 수동 확인 경로는 이번 점검에서 확인하지 못했다.
- TikTok 검수 탭을 보고 있는 중 YOUTUBE 캘린더 예약을 변경해도 활성 탭은 TikTok으로 남는다. 취소된 플랫폼과 재예약 대상이 어긋날 수 있다.
- 중지 채널의 `이 소재로 영상 만들기`가 활성화돼 있고 클릭 시 `ACTIVE_CHANNEL_NOT_FOUND` 원시 코드가 나온다.
- 90일 분석을 선택해도 패널 설명은 `최근 7일간`이다.
- 유효 refresh 쿠키가 있어도 access가 사라지거나 만료되면 자동 `/auth/refresh` 없이 다시 로그인해야 한다. 쿠키 제거 모사와 장시간 점검 중 재로그인 필요 상황으로 확인했다.
- 검수의 role=tab에는 ArrowRight 전환이 없다. 마우스 클릭은 작동한다.
- 완료된 샘플 실행에서도 이전 실패 코드가 화면에 남는 경우가 있었다. 완료 상태와 최근 오류/시도 이력을 구분해 보여줘야 한다.
- 생성 초안의 계정 연결이 실패한 뒤 닫으면 새 초안이 홈/분석 선택에 즉시 반영되지 않아 새로고침이 필요했다.
- renderer circuit breaker가 걸려도 화면에서 제공자 스위치를 조회/해제할 조작이 없다. 첫 저장소 실패에서 이 복구 경로 부재도 관찰했다. 원시 `The provider kill switch is enabled.`만으로는 운영자가 화면에서 복구할 수 없다.
- 15초 QA 설정은 입력/생성 전에 차단되지 않고 실제 영상 렌더 뒤 `Content duration is below the platform minimum.`으로 보류됐다. 정책 차단은 정상이지만, 적용 중인 플랫폼 길이 규칙을 설정 화면에서 안내하면 불필요한 비용을 피할 수 있다. 30초로 수정해 새 샘플을 요청했다.

## 테스트 환경과 실패 시도 기록

브라우저 접속용 포트를 추가하면서 기존 **임시 acceptance MinIO 컨테이너를 재생성해 이전 테스트 객체가 유실**됐다. 기존 acceptance DB의 재사용 캐시가 없는 객체를 가리켜 첫 샘플은 `RENDER_FAILED: The specified key does not exist.` 후 renderer circuit breaker로 보류됐다. 이 시도를 제품의 정상 환경 렌더 결함으로 세지 않았다. 이전 테스트 DB·문서·보안 결과는 남았고, 유실 객체는 원본 백업 없이 그대로 복구됐다고 주장하지 않는다. 재생성 가능한 테스트 영상이다. 개발 MinIO/DB/Redis는 손대지 않았다.

원인을 구분한 뒤 새 UX 전용 DB에 migration/seed를 실행하고 샘플 제작을 다시 진행했다. 최종 3플랫폼 샘플은 수집·대본·이미지·음성·렌더·정책·검수·완료까지 통과했다. 임시 저장소 재생성 문제를 숨기거나 최초 실패를 성공으로 세지 않는다.

점검용 스크립트의 잘못된 `exact` 라벨, 현재 데이터에 존재하지 않는 상태 option, 너무 빠른 seek 스크린샷 등의 실행 실패도 있었다. 해당 조작은 실제 DOM/상태에 맞춰 다시 확인했다. 스크립트 locator 오류를 제품 버그로 분류하지 않았다. video 준비 상태만으로 프레임 시각 검증을 완료하지 않고 `seeked` 후 프레임을 다시 봤다.

## 미실행·제한

- 실 SNS OAuth·실 업로드·실 analytics·유료 생성 공급자·실 한국어 음성 품질·사용 권리·운영 공개 URL/HTTPS·부하·원격 CI는 이 UX 점검으로 확인하지 않았다.
- RSS/출처 사실성, 각종 권리/정책 위험의 모든 조합, 모든 부분 재생성 범위의 새 영상 완성, 실제 전략 적용/되돌리기 후 결과 변화, 충분한 실험 표본 비교를 전부 새 브라우저 여정으로 재현하지 않았다. 화면 누락·미실행·기존 백엔드 회귀 결과를 서로 구분했다.
- lint/typecheck/build/security/전체 monorepo 검증은 서비스 코드를 바꾸지 않았으므로 반복하지 않았다. 이번의 새 결함은 기존 통과 결과를 덮어쓰거나 임의로 수정하지 않고 독립된 실제 UX 증거로 남긴다.
- 명세에서 애초 제외한 팀/모바일 앱/롱폼/자유 편집기/결제 SaaS/인과 통계 기능은 결함으로 세지 않는다. 반면 허용 출처·운영 일정 수정·플랫폼 독립 메타데이터·재예약·분석 운영처럼 목표에 필요한 화면은 제외 기능으로 임의 처리하지 않는다.

### 완료한 실행

- browser `pageerror`는 0이었다. 서버 예약 500 및 UX 결함이 없다는 뜻은 아니다.
- 최초 3플랫폼 샘플 run: `cmuvnuz5u002anq013vi2m5vr`; 콘텐츠: `cmuvnuzke0007oe01kud6gz9i`.
